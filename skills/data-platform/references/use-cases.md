# 数据处理使用案例

两个案例执行相同的数据处理代码，区别在运行位置。本页是操作示例，不代表已经创建资源或运行任务。

## 共用的数据处理流程

```text
DataClient 按特征搜索 → 确认范围并记录本次输入 ID 清单
  → 读取 TD → 执行业务处理 → 生成输出 TD
  → 上传并 RegisterData 登记 → 回读核验 → 返回结果数据 ID
```

- 搜索特征使用平台已有字段，如采集任务名前缀、数据类型、采集时间和录制时长；具体字段见 [平台接口说明](api.md)。内容特征由脚本读取候选数据后判断，不假设平台已支持语义搜索。
- 脚本 main.py 从 `JOB_PARAMETERS_FILE` 读取参数，使用 [DataClient](data-client.md) 查询和读取，按 [TD 规范](td-format.md) 写出，按 [上传规范](data-transfer.md) 登记结果。

两种方式可使用同一份 params.yaml，以下筛选值为示例，执行前替换为用户确认的条件：

```yaml
filter:
  taskNamePrefix: inspection
  recordingDurationRange:
    min: 60s
output_prefix: job-results/feature-processing/<本次运行ID>/
```

- 示例含义：搜索采集任务名以 inspection 开头、录制时长至少 60 秒的数据；业务处理逻辑由用户脚本或 Agent 按要求实现。
- 用户明确限定的数据 ID、数量和处理范围优先；程序记录实际处理清单，每份输出生成独立数据 ID，不覆盖输入。

## Case 1：使用开发机直接运行代码

用户示例：

> 帮我申请一台开发机，按采集任务名前缀和录制时长搜索数据，运行我的处理脚本，将结果保存为 TD 并上传登记到数据平台。

Agent 执行：

1. 确认搜索条件、处理逻辑和范围，明确运行环境。
2. 按 [开发机使用](dev-pod.md) 补齐用户名、CPU／内存、GPU 数量和 SSH 公钥，确认配置、检查资源后申请；已有合适开发机可直接使用。
3. 通过 VPN SSH 登录，将代码和参数放入本次独立目录，在独立 Python 环境安装固定版本依赖；先读取少量样本检查数据和处理逻辑。
4. 在开发机上执行脚本，将标准输出和错误输出保存为 run.log。运行环境使用本次确认的 prod／test，日志、进程和退出码通过 SSH 查看。
5. 程序使用 DataClient 按特征搜索并处理数据，完成 TD 上传和 RegisterData 登记，输出源数据与结果数据 ID 的对应关系。
6. Agent 核对退出码、日志、登记记录和远端 TD，交付结果；开发机保持原状态，用户要求释放时再按一次确认流程处理。

在开发机项目目录内运行的命令示例，当前 Python 应已是准备好的虚拟环境：

```sh
# ENV 使用本次确认的环境；用户指定 test 时相应替换。
ENV=prod JOB_PARAMETERS_FILE="$PWD/params.yaml" python -u main.py > run.log 2>&1
```

- 长任务需维持 SSH 会话，或使用该开发机已验证的后台运行方式；不能把 SSH 断开后进程是否存活当成既定事实。
- 本方式不创建处理 Job，平台 Job 日志接口不包含这次脚本运行；任务日志通过 SSH 查看，需要长期保留时保存到用户指定的持久化存储。

## Case 2：本地构建镜像，提交 Job 运行

用户示例：

> 按这些特征搜索数据，用我的处理代码在本地构建镜像，提交平台 Job 执行，输出 TD 并上传登记到数据平台。

Agent 执行：

1. 确认与 Case 1 相同的数据条件、处理逻辑和结果要求；检查本机 Docker 及镜像仓库权限，缺少 Docker 时提示安装并启动。
2. 在独立构建目录放入同一份 main.py、项目模块和固定版本 requirements.txt，按 [镜像编译](jobs.md#镜像编译) 使用常用基础镜像构建。
3. 核对任务启动入口，业务参数和数据放在运行阶段读取。
4. 先用小样本测试镜像，再以唯一版本推送到用户有权限且服务允许的任务仓库，记录镜像地址和 digest。
5. 按 [任务提交与跟踪](jobs.md) 确认资源、检查可用量，将镜像填入 spec.image、params.yaml 内容填入 parametersYaml，调用 CreateJob。
6. Job 执行同一段“搜索 → 处理 → TD 上传登记”代码；Agent 通过 GetJob 和 GetJobLogs 查询状态及运行日志。
7. 核验任务状态、登记记录和远端 TD，交付结果。Job 成功与业务处理满足要求分别确认。

- 提交使用集群可达且符合白名单的镜像地址；平台挂载 params.yaml 并注入 JOB_PARAMETERS_FILE 和 ENV，不能把它们替换成开发机路径。
- 本方式只使用现有镜像 Job，不代表平台已有代码包执行或远程镜像构建服务。

## 结果交付

| 内容 | Case 1 | Case 2 |
|---|---|---|
| 运行标识 | 开发机 Pod ID、本次运行目录 | Job ID、镜像版本 |
| 运行日志 | 开发机 run.log 与退出码 | GetJobLogs 与 Job 执行报告 |
| 数据结果 | 源数据 ID、结果数据 ID、TD 存储地址、处理统计 | 同左 |
| 校验范围 | 实际检查的 topic、消息数和样本 | 同左 |

两种方式都通过 DataClient 读取登记后的结果，不提供数据下载接口或签名下载地址。
