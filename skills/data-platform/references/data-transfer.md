# 数据读取与上传规范

## 数据读取

- 用户说“下载数据”时，先按数据 ID 或查询条件取得元数据，再通过 `DataClient.open_td` 读取；具体代码见 [DataClient 使用](data-client.md)。
- 按元数据选择实际 provider／bucket 和可达网络，不拼接存储路径，不自动把整个数据集复制到本机。
- 搜索返回多条记录时先确认处理范围；流式查询得到的是精简元数据，业务需要完整字段时再 GetData。

## 上传前确认

| 内容 | 要确认什么 |
|---|---|
| 上传文件 | 本地文件路径、真实格式和需要上传的范围 |
| 数据身份 | 新数据使用独立 UUID，不复用输入数据 ID |
| 上传位置 | 平台配置的默认对象存储，或用户明确指定且平台支持的 provider／bucket |
| 元数据 | 展示名称、实际文件大小、校验和，以及能从内容核实的类型和统计 |

- 自定义处理任务的结果统一为 TD，生成规范见 [TD 文件生成规范](td-format.md)。原始数据按真实格式和平台已有分类上传，不将任意文件改名为 TD。

## 上传与登记

1. 调用 CreateUploadURL，或使用 SDK 上传客户端取得服务选择的位置；使用唯一对象路径，保留真实 provider、bucket、objectKey。
2. 上传文件并核验远端内容。具体上传、计算 SHA256 和登记代码见 [DataClient 使用](data-client.md) 的第 8–9 节。
3. 上传核验成功后调用 RegisterData，登记同一数据 ID、实际存储位置、文件大小、校验和及已核实的内容统计。
4. 调用 GetData 确认登记记录；TD 使用 DataClient 回读，核对 topic、schema、消息数量和代表性样本。

- 上传成功不会自动生成元数据记录；结果登记是任务交付的一部分，返回数据 ID、持久化地址和核验范围。
- 登记失败保留已上传对象，优先恢复登记，不重新生成一份相同结果；遇到已有 ID 先核对原记录。
- 数据类型、设备、帧率、时间范围和 topic 统计按实际输出填写，不复制已经失效的输入元数据。

## 存储凭据

- 临时凭据由平台 API 和 SDK 管理；优先复用现有认证，不要求用户把 AK/SK 放入脚本或任务参数。
- 签名上传 URL 仅用于文件上传，不作为数据的长期地址。返回用户的是登记后的数据 ID 和不含签名参数的存储 URI。
